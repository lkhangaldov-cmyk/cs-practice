\- git diff — показывает различия между версиями файлов: что добавили, удалили или изменили.

\- git show — показывает информацию о конкретном коммите: автора, дату, сообщение и изменения в файлах.

\- git log — показывает историю коммитов проекта: кто, когда и какие изменения вносил.

\- git log -S"текст" — находит коммиты, в которых изменилось количество вхождений указанного текста в файлах. Помогает выяснить, когда строка была добавлена или удалена.

\- git blame файл — показывает для каждой строки файла последний коммит, в котором она была изменена, а также автора и дату изменения.

Главное отличие: diff сравнивает версии, show показывает конкретный коммит, log отображает историю, log -S ищет изменения конкретного текста, а blame помогает установить, кто и когда изменил определённые строки.




git restore и git restore --source

\- `git restore <файл>` — восстанавливает файл из индекса (по умолчанию), отменяя изменения в рабочей директории. Если изменения не были сохранены в индексе, они будут потеряны.

\- `git restore --source=<источник> <файл>` — восстанавливает файл из указанного источника, например коммита `HEAD` или другого коммита. Это позволяет вернуть версию файла из выбранного состояния репозитория.

\### Что произошло бы с моими правками?

Команда `git restore <файл>` отбросила бы незакоммиченные изменения в рабочей директории, заменив файл версией из индекса.

Kоманда `git restore --source=HEAD <файл>` восстановила бы файл из последнего коммита, заменив его содержимое и потенциально потеряв как незакоммиченные изменения, так и изменения, уже добавленные в индекс.




### `git revert` vs `git reset --hard`

`git revert <commit>` отменяет изменения выбранного коммита, создавая новый коммит. При этом история сохраняется.

`git reset --hard <commit>` перемещает текущую ветку на указанный коммит и сбрасывает индекс и рабочую директорию к его состоянию. Более поздние коммиты исчезают из текущей истории ветки, а незакоммиченные изменения могут быть потеряны.

В опубликованной истории безопаснее использовать `git revert`, потому что он не переписывает существующую историю и не мешает другим разработчикам синхронизировать свои ветки.





Тег Git vs Ветка
Тег (tag) — это фиксированное имя для конкретного коммита, обычно используемое для обозначения релиза или версии, например v1.0. Обычно он остаётся привязанным к тому же коммиту.
Ветка (branch) — это перемещаемый указатель на последний коммит в определённой линии разработки. Когда добавляются новые коммиты, указатель ветки перемещается вперёд.
Главное отличие: тег обозначает конкретную версию, а ветка отслеживает продолжающуюся разработку.
